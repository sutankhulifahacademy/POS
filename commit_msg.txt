## Reports — Profit/Loss now uses paket_items for COGS

All COGS calculations in report endpoints now handle paket items:
- /reports/profit-loss: headline, by-product, by-category, by-day
- /reports/sales: by-product breakdown

For regular items: COGS = products.cost × quantity
For paket items: COGS = SUM(component.cost × component.quantity)
  for each item in paket_items

The SQL uses a CASE expression with jsonb_typeof check:
  WHEN jsonb_typeof(elem->'paket_items') = 'array'
       AND jsonb_array_length(elem->'paket_items') > 0
  THEN (SELECT SUM(pc.cost * pi.quantity)
        FROM jsonb_array_elements(elem->'paket_items') pi
        JOIN products pc ON pi.product_id = pc.id)
  ELSE p.cost * elem.quantity

## Backend — SaleItem model now accepts paket_items

Added paket_items field to SaleItem model so Pydantic doesn't strip it:
  class SaleItem(BaseModel):
      ...
      paket_items: Optional[list[dict[str, Any]]] = None

Without this, paket_items sent from POS/Dine-In were silently dropped
during validation and never stored in sales.items JSONB.

## Database — Removed unused columns

Dropped product_type and bundle_items from products table:
  ALTER TABLE products DROP COLUMN product_type;
  ALTER TABLE products DROP COLUMN bundle_items;

These were added in the previous paket approach (v1.0) but are no
longer needed. Paket detection is now purely category-based.

Updated postgres_schema.sql to reflect the removal.
